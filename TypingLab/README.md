# TypingLab

한녕 등 macOS 입력기의 실제 자동 전환을 확인하는 작은 테스트 앱입니다.

1. 위쪽 **테스트 문장**에 원문을 붙여넣습니다. 한 줄에 한 문장입니다.
2. 입력기와 키 입력 간격, 반복 횟수를 선택합니다.
3. **시작**을 누르면 아래 **실제 타이핑** 칸에 두벌식 물리 키를 순서대로 보냅니다.
4. 문장마다 아래 칸을 비우고 결과를 기록합니다. 서로 다른 부분은 빨간색으로 표시합니다.
5. **결과 저장**으로 원문, 실제 결과, 입력기, 키 수, 소요 시간을 JSON으로 저장합니다.

처음 실행할 때 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 **TypingLab**을 허용해야 합니다. 권한 상태는 앱 위쪽에 표시합니다.

한글은 두벌식 키로 분해합니다. 예를 들어 `안녕 slack에서 ㅋㅋ`는 `dkssud slackdptj zz`를 누릅니다. 실제 출력은 선택한 입력기가 결정합니다. 각 문장 끝에 변환 확정을 위한 Space를 한 번 누르며, 비교는 시작과 끝의 공백 및 한글 정규화 차이를 제외합니다. 문장 내부의 공백 차이는 그대로 검사합니다.

공개 CoreGraphics API로 이 앱의 프로세스에만 키 이벤트를 보냅니다. 테스트 중에는 이 앱을 활성 창으로 유지해야 합니다. 다른 앱이나 입력 칸으로 포커스를 옮기면 일시정지합니다. 비활성 창에서는 키 이벤트가 입력기를 건너뛰는 현상이 관측되어 비활성 실행을 막았습니다. 클립보드나 유니코드 삽입으로 타이핑을 대체하지 않습니다. 아래 칸은 표준 NSTextView입니다. 카카오톡·Slack 특유의 입력창 동작은 별도 확인이 필요합니다.

현재 지원 범위는 두벌식 한글, 한글 자모, 영문, 숫자, ANSI 키보드 기호입니다. 이모지 등 물리 키로 변환하지 못하는 문자는 시작 전에 알려 줍니다. 한녕 모델과 저장된 교정을 수정하지 않습니다. 기본 문장은 앞서 학습 데이터 중복 검사를 통과한 20문장입니다.

빌드·실행:

```sh
./script/build_and_run.sh
```

빌드만: `./script/build_and_run.sh --build`

통합 확인용 3문장 반복·일시정지·중단·재시작 검사: `./script/build_and_run.sh --smoke` (손쉬운 사용 권한 필요)

단위 검사: `swift test` (XCTest를 위해 전체 Xcode의 개발 도구 경로 사용)
